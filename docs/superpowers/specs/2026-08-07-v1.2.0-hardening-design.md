# v2.0.0 hardening release

## Goal and release boundary

Publish a `v2.0.0` release through a GitHub pull request. The release fixes
confirmed request-routing, error-mapping, token-cache, and HTTP-boundary
defects; corrects the published webhook guidance; adds Laravel 13
compatibility; drops security-EOL Laravel 11 support; and makes the supported
combinations verifiable in CI.

The version is conveyed by the annotated `v2.0.0` Git tag after the PR is
merged. Composer metadata does not contain a separate version field.

The only intentional breaking change is removal of Laravel 11 support. Laravel
11 security support ended on 12 March 2026 and Composer blocks every framework
version because of active advisories. The release deliberately does not change
the public resource API, tighten DTO hydration rules, or make broad
PHPStan-max remediation changes.

## HTTP request boundary

`DokapiClient` will distinguish Dokapi API/token requests from a presigned
document upload.

API routes will be resolved relative to the configured base URL, preserving a
path prefix such as `/v1`. Route definitions may keep their current leading
slashes; one internal normalizer removes the leading slash only for a relative
API route. Absolute token URLs remain absolute and are never combined with the
API base URL.

Identifiers inserted into API paths (webhook and incoming-document ULIDs) will
be encoded with `rawurlencode`. Invalid values therefore remain one path
segment and are handled by Dokapi as an ordinary API error rather than changing
the authenticated target URL.

Dokapi API and OAuth requests retain the configured timeouts, TLS setting,
user agent, and `dokapi.http` custom options. `http_errors` is always set to
`false` after options are merged so the package consistently maps non-2xx
responses to its documented `DokapiRequestException` subclasses.

A presigned upload is an untrusted cross-origin request boundary. It will use
only the package's explicit transport defaults, `Content-Type: application/xml`,
and the XML body; it will not inherit `dokapi.http` headers, cookies,
authentication, or other request-specific options. Redirects will be disabled
for the upload. The upload URL must be an absolute HTTPS URL before it is used.
This protects API credentials and custom headers from being sent to an upload
host while retaining the public `uploadDocument()` method and normal Dokapi
presigned-upload flow.

## OAuth token contract

`getAccessToken()` will accept a configured static token exactly as it does
today. For OAuth responses it will require a non-empty string `access_token`.
It will cache only when `expires_in` is a positive numeric value whose lifetime
exceeds the 60-second safety margin. The cache duration is `expires_in - 60`;
tokens expiring in 60 seconds or less are returned but not cached. A missing or
invalid `expires_in` also returns the token without caching. This avoids
reusing an already expired token without rejecting otherwise usable OAuth
servers that omit an expiry field.

## Package, documentation, and CI

Composer constraints will support Laravel 12 and 13 through the matching
Illuminate Cache/Support and Orchestra Testbench major versions. Laravel 11 is
intentionally excluded because its security support has ended and it cannot
resolve under Composer's advisory blocking. PHP remains PHP 8.3+. Guzzle
remains on its current 7.x line, with the lower bound raised only as required
for Laravel 13 compatibility; Guzzle 8 is excluded because it does not satisfy
Laravel's current framework constraint.

The README will state Laravel 12/13 support, document `DOKAPI_CACHE_TOKEN`
and `DOKAPI_WEBHOOK_SECRET`, and use the existing
`Dokapi::api()->webhooks->verifySignature()` API in its webhook example. The
example checks that both the signature and configured secret are present before
verification.

A GitHub Actions workflow will resolve dependencies without committing the
ignored lock file and test Laravel 12/Testbench 10 on PHP 8.4 and Laravel
13/Testbench 11 on PHP 8.5. Each job will validate Composer metadata, audit
resolved packages, run PHPUnit, and run PHPStan.

## Test contract

New focused Guzzle mock/history tests will prove all observable behaviour:

- an API request against a `/v1` base URL reaches `/v1/...`, while the OAuth
  endpoint remains its configured absolute URL;
- hostile identifier text is percent-encoded and cannot replace the intended
  webhook or incoming-document endpoint;
- a presigned upload omits Authorization, custom API headers, cookies, and
  custom HTTP options, sends XML with its required content type, does not
  follow redirects, and rejects non-HTTPS or relative URLs;
- a configured `http_errors=true` still produces the mapped validation
  exception for a 4xx response;
- OAuth tokens with a normal expiry are reused, while 60-second, malformed,
  missing, and non-positive expiries are not cached; and
- malformed or blank OAuth access tokens produce a package exception before
  any authenticated API request is made.

Existing public API, DTO, resource, and webhook-signature tests remain in the
suite. The full suite and PHPStan must pass locally and in the CI matrix before
the PR is considered ready.

## Release flow

The branch is `release/v2.0.0-hardening`. After the implementation is reviewed
and verified, it will be pushed and a pull request opened against `main`.
After that PR is merged, `main` will be re-verified and tagged with annotated
tag `v2.0.0`, then pushed so Packagist can discover the release.
